How a photo becomes a match

  1. カシャッ

    1

    Ingest

    Bulk uploads go straight onto a queue. Celery workers take it from there, so the API never blocks and requests never time out.

  2. 2

    Compress

    Every photo is compressed in the background, automatically.

  3. 3

    Embed

    InsightFace turns each face it finds into an embedding: a vector that lands close to other photos of the same person.

  4. 4

    Index

    The vectors live in PostgreSQL with pgvector, under an HNSW index.

ドン！

~98% matching accuracy

5 · Match

A new face is matched against all of them in under a second.

I architected and scaled this pipeline at Plandaro. It processes thousands of event photos, and the background workers mean a bulk upload never holds up the API.

  • InsightFace
  • PostgreSQL + pgvector
  • HNSW
  • Celery

How the index finds a face without checking every one

Each dot is a face from a photo, and photos of the same person sit close together. Pick any spot to stand in for a new face. The search then has to find the five faces nearest to it.

The live demo needs JavaScript. The three steps below describe what it shows.

Layer 1

Layer 0

  1. Layer 2. Start at the top: few faces, long links. Hop to whichever neighbour is closest to the new face.
  2. Layer 1. Drop down a layer. More faces, shorter hops.
  3. Layer 0. Every face is here. Search the neighbourhood properly and keep the five closest.

Every server keeps a list of keys.

People leave. Their keys do not.

Interactive, runs in your browser

How a departed colleague's key gets found and removed

I designed and built an automated system that did this audit, so nobody had to do it by hand. Here it is in miniature. Click a name to have that person leave, then run the audit.

The live demo needs JavaScript. In short: the audit compares every key on every server with the staff directory, removes keys whose owner has left, and emails a report.

Directory who works here

    Report sent by email

    A toy version with made-up names. The real system was built with Python, Jenkins, LDAP and SMTP. It checked the LDAP directory against server configurations regularly, with nobody pressing a button.
